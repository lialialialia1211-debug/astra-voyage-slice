## 2. 視覺方向

### 2.1 核心風格

第一章採用原創的「潮界機能奇幻」：

- 海洋奇幻 70%。
- 現代機能 30%。
- 主要視覺語彙：航線、船舶、錨、潮汐、封緘、羅盤、海圖、繩結、航海燈、侵蝕結晶。
- 服裝可參考《鳴潮》《絕區零》的不對稱剪裁、材質層次、功能性掛件與輪廓節奏。
- 不直接複製既有角色、服裝輪廓、標誌、武器造型或特徵性配色。

### 2.2 材質與色彩

- 主材質：防水織物、舊皮革、霧面金屬、陶瓷護片、玻璃核心、潮蝕結晶。
- 避免所有區域都使用同一種高亮塑膠或霓虹材質。
- 發光部位只用於元素核心、導航刻度、錨印與黑潮侵蝕。
- 每名角色需要一個主色、一個輔色及一個小面積識別色。
- 場景以低飽和海色為底，角色識別色應能從背景中清楚分離。

### 2.3 服裝總則

- 八名角色的服裝完全個別化，不使用共通制服。
- 每名角色只製作一套可重複使用的正式代表服裝。
- 一套服裝必須同時支援故事立繪、戰鬥立繪、卡面與艙室介面。
- 可拆部件、破損、濕潤或衣著狀態變化只存在於特定 CG，不建立第二套通用服裝。
- R18 相關角色及場景資料必須明確標示參與者均為成年人。

### 3.1 昭黎的六屬性表現

昭黎的屬性由主手武器決定，戰鬥中不能切換。因此：

- 基礎服裝維持中性主配色。
- 元素辨識集中於武器、胸前或腰側的小型核心、局部能量刻度。
- 不為六屬性各畫一套昭黎立繪。
- 程式端可對核心光、戰鬥特效及 UI 標記套用火、水、土、風、光、闇六色。
- 一般攻擊、奧義與元素特效必須跟隨當前主手武器。

## 10. AVG 畫面相容規則

新版 AVG 採三人同台：左、中、右最多同時三名角色。

人物立繪必須符合：

- 半身裁切後，臉部與手勢仍完整可讀。
- 左右鏡像時不出現錯字、單側標誌或武器結構錯誤；若不可鏡像，交付時需註明。
- 當前說話者會由程式端提高亮度、放大並向前移動。
- 非說話者會降低亮度，不需要另外提供暗色版本。
- 角色入場、退場、震動、淡化與受擊閃白由程式端處理。

背景及 CG 不可把唯一關鍵資訊放在：

- 對話框遮蔽區。
- 手機瀏海或瀏覽器安全區。
- 左、中、右角色最常遮擋的位置。

## 13. 批次驗收與整合規則

每個批次交付後，整合流程會檢查：

1. 預期路徑與檔名是否存在。
2. 圖片尺寸、格式與 Alpha 是否符合規格。
3. Manifest 是否能解析全部素材 ID。
4. 劇本、戰鬥與角色資料是否引用不存在的素材。
5. 缺圖時是否顯示開發用 fallback，而不是造成白畫面或流程中斷。
6. WebP 衍生檔是否成功產生。
7. 三人 AVG 舞台、卡面、戰鬥及 CG 裁切是否正常。

依專案 QA 規則，正式驗收不使用本機伺服器或本機建置結果；整合後必須推送工作分支，透過 GitHub Actions 的 `Remote QA - GitHub Pages` 工作流程驗證，並只在以下固定環境檢查：
