# 原創成人向艦隊 RPG：美術生產與交付規格

- 版本：1.0
- 日期：2026-08-03
- 對應設計：`gbf-inspired-adult-web-slice-design.md`
- 使用者交付數量：63 個 PNG 資產
- Codex 後續製作：UI 背景、框體、徽章、互動元件、WebP 轉檔與程式整合

## 1. 分工

### 1.1 使用者負責

- 成年男女艦長美術。
- 四名成年女性隊員美術。
- 12 把武器。
- 2 個召喚核心。
- 3 種一般敵人與海上 Boss 的兩種狀態。
- `CHR_02` 的三張正式成人事件 CG。

### 1.2 Codex 負責

- 使用圖像生成工具製作港都、深海、星空、招募、戰鬥及私人艙室背景。
- 製作黃銅／青光裝飾、稀有度框、屬性徽章、按鈕材質與模式條框體。
- 使用 React、CSS 與 SVG 製作文字、按鈕狀態、焦點、排版及戰鬥動畫。
- 將使用者交付的 PNG 轉成適合網頁載入的 WebP。
- 驗證檔名、尺寸、透明度、安全區及缺圖狀態。
- 將資產 ID 連接到角色、武器、敵人與事件資料。

## 2. 交付資料夾

請將全部資產放在單一 `art-drop` 資料夾，結構如下：

```text
art-drop/
  captains/
    cap_m/
    cap_f/
  characters/
    chr_01/
    chr_02/
    chr_03/
    chr_04/
  weapons/
  summons/
  enemies/
  bosses/
  events/
    chr_02/
```

檔名與路徑必須完全符合 `art-asset-checklist.csv` 的 `expected_path` 欄位。顯示名稱不寫入檔名，之後直接在遊戲資料中修改。

## 3. 全域技術規格

| 項目 | 規格 |
|---|---|
| 色彩空間 | sRGB IEC61966-2.1 |
| 位元深度 | 8-bit RGBA；不需要 HDR |
| 交付格式 | PNG；需要透明背景的資產必須保留直通 Alpha |
| 透明邊緣 | 不得帶白邊、黑邊或預乘 Alpha 暈邊 |
| 圖片文字 | 不得烘焙名稱、數值、台詞、浮水印或 UI 文字 |
| 檔名 | 小寫英數與底線；不得使用空格、中文、括號或版本尾碼 |
| 方向 | 人物與敵人預設面向畫面中央；武器保持完整且不可裁切 |
| 來源檔 | PSD、CLIP 或 KRA 可自行保留；整合時只要求符合規格的平面 PNG |
| 網頁轉檔 | Codex 統一輸出 WebP；一般圖品質 85、事件 CG 品質 90 |
| 版本更新 | 直接覆蓋同名 PNG；需要新增構圖時建立新的資產 ID，不加 `_final2` |

所有人物皆為成年人。正式成人 CG 不得使用第三方作品的角色、服裝圖樣、標誌或其他受保護素材。

## 5. 艦長與隊員立繪

### 5.1 主立繪與表情

| 項目 | 規格 |
|---|---|
| 畫布 | 2048×3072 px，透明背景 |
| 人物錨點 | 雙腳基準中心位於 `(1024, 2960)` |
| 安全區 | 左右各 164 px、頂端 164 px、底端 80 px |
| 表情 | neutral、happy、tense／angry、hurt，共四張完整對齊 PNG |
| 構圖 | 全身或至少到小腿；各表情的身體、服裝與輪廓位置完全一致 |
| 陰影 | 不要繪製地面投影；程式會統一加入陰影 |

艦長使用 `tense`；四名隊員使用 `angry`。這兩個詞只影響檔名，不限制表情細節。

### 5.2 戰鬥姿勢

| 項目 | 規格 |
|---|---|
| 畫布 | 1600×1600 px，透明背景 |
| 人物錨點 | 腳底中心位於 `(800, 1504)` |
| 安全區 | 四周至少 96 px |
| 姿勢 | 一張可長時間顯示的戰鬥待機姿勢 |
| 武器 | 完整包含於畫布；不得接觸邊界 |
| 動畫 | 程式以位移、縮放、震動、閃光及殘影製作，不需逐格圖 |

### 5.3 角色卡

| 項目 | 規格 |
|---|---|
| 畫布 | 1024×1536 px，不透明背景 |
| 臉部安全區 | X 15%–85%，Y 12%–58% |
| UI 保留區 | 頂端 12% 放稀有度；底端 20% 放名稱與數值 |
| 構圖 | 半身或膝上；視線朝向畫面中央 |
| 文字 | 不得含名稱、稀有度、屬性、數值或標誌 |

### 5.4 私人艙室姿勢

| 項目 | 規格 |
|---|---|
| 畫布 | 2048×3072 px，透明背景 |
| 錨點 | 與主立繪相同：`(1024, 2960)` |
| 一般姿勢 | 每名隊員一張 `cabin_base` |
| 替換服裝 | 第一版只要求 `chr_02_cabin_outfit_02.png` |
| UI 安全區 | 角色臉部不可位於最右側 32%，該區會顯示關係面板 |

## 6. 成人事件 CG

第一版要求 `CHR_02` 三張正式成人事件 CG。規格不限定具體姿勢或行為，但畫面中的人物必須全部明確為成年人，且不得使用第三方角色或素材。

| 資產 ID | 用途 | 尺寸 |
|---|---|---:|
| `evt_chr02_bond03_cg01` | 關係 Lv.3 主事件 | 2560×1440 |
| `evt_chr02_status_cg01` | 特殊狀態收藏事件 | 2560×1440 |
| `evt_chr02_defeat_cg01` | 首次敗北收藏事件 | 2560×1440 |

共同規格：

- 色彩空間為 sRGB，交付 PNG。
- 不烘焙台詞、對話框、按鈕、事件名稱或浮水印。
- 重要人物與動作保留在 X 6%–94%、Y 6%–78%。
- 底端 22% 可能顯示事件文字，不放置關鍵臉部或細節。
- 若需要多個差分，先交付上述三張基礎圖；差分將在下一輪以新的資產 ID 加入。

需要 12 把武器，讓十格武器盤具有兩個替換選項。

| 項目 | 規格 |
|---|---|
| 畫布 | 1024×1024 px，透明背景 |
| 物件安全區 | 四周至少 92 px |

## 10. Codex 生成的 UI 與背景規格

下列資產由 Codex 在實作階段使用圖像生成工具製作；使用者不需繪製，但清單保留完整尺寸以利整合與審閱。

### 10.1 背景

| 資產 | 尺寸 | 需求 |
|---|---:|---|
| 標題港都 | 2560×1440 | 明亮地表文明、海軍藍與黃銅 |
| 港都主畫面 | 2560×1440 | 遠征港、海面與星空航行伏筆 |
| 招募艙 | 2560×1440 | 魔導科技觀測艙，不含人物與文字 |
| 編隊／武器盤底圖 | 2560×1440 | 低對比航艦操作台，不干擾資訊閱讀 |
| 陸地戰鬥 | 2560×1440 | 港都防衛區，角色站位區保持乾淨 |
| 海上 Boss 戰 | 2560×1440 | 深海青光與警戒紅，不含 Boss |
| 私人艙室 | 2560×1440 | 舷窗、床座或沙發；右側保留 UI 區 |
| 星空結尾 | 2560×1440 | 未知訊號與遠方星體，不含文字 |

### 10.2 UI 裝飾

- 普通、R、SR、SSR 四種角色／武器框：1024×1024，透明 PNG。
- 火、水、風、土、光、闇六枚屬性徽章：512×512，透明 PNG。
- 一般、滑過、按下三種無文字按鈕底板：1024×384，透明 PNG。
- Boss 模式條框：2048×256，透明 PNG。
- 奧義充能條框：2048×256，透明 PNG。
- 對話框裝飾底板：2048×512，透明 PNG。
- 頁籤底板：1024×256，透明 PNG。

功能性文字、數字、鍵盤焦點、停用狀態與點擊區域全部由 HTML／CSS 建立，不使用生成圖片中的文字。

## 11. 整合前檢查

每批交付前請確認：

1. `art-asset-checklist.csv` 中對應列已標示為 `ready`。
2. 檔名與路徑完全相符，沒有多餘版本尾碼。
3. PNG 尺寸正確，透明圖沒有底色。
4. 人物與狀態差分的錨點一致。
5. 角色卡與 CG 的重要內容避開 UI 保留區。
6. 圖片內沒有文字、浮水印或第三方標誌。
7. 所有成人角色與畫面人物均明確為成年人。

完成後可將整個 `art-drop` 資料夾壓縮提供，或直接放入共同工作區。Codex 會依檢查表批次驗證尺寸、檔名與缺漏，再轉檔及連接遊戲資料。
