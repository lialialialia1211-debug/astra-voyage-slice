# Astra Voyage 陸地遠征篇設計規格

日期：2026-08-04

狀態：已完成對話核准，等待書面規格確認

## 1. 目標

把目前的單一路徑快速切片擴充為第一個可重複遊玩的正式章節中樞。玩家完成招募與編隊後，會先在陸地區域地圖推進四個節點，透過戰前／戰後劇情、AP、固定掉落、角色強化與武器強化建立完整循環；擊破陸地首領後才解鎖既有的海洋航線與潮汐守望者。

本階段必須：

- 維持純前端、單機、本機存檔與私人 GitHub 同步。
- 重用既有角色、表情、敵人與背景美術，不要求新的美術交件。
- 保留成人內容為私人艙室的可選收藏，主線與戰鬥養成不依賴成人內容。
- 讓既有第 1 版存檔安全遷移，不重置關係、收藏、隊伍或武器盤。

## 2. 不在本階段的範圍

- 後端、帳號、雲端存檔、多人功能與排行榜。
- 付費 AP、付費道具、每日任務、登入獎勵與商店。
- 自動周回、掃蕩券、隨機詞條、裝備突破、角色突破與 Lv.10 以上養成。
- 自由移動地圖、3D 場景或即時動作戰鬥。
- 新的成人事件線或成人內容對戰鬥能力的加成。
- 海洋篇與星空篇的新關卡；本階段只解鎖既有潮汐守望者入口。

## 3. 玩家流程

新玩家主流程為：

1. 成年確認。
2. 選擇艦長。
3. 序章、固定十連招募與四人編隊。
4. 進入陸地區域地圖。
5. 選擇已解鎖節點並查看 AP、敵人及掉落。
6. 首次挑戰先播放戰前劇情，之後進入武器盤確認頁。
7. 按下出擊時檢查並扣除 AP，建立可持續保存的挑戰紀錄。
8. 勝利後發放固定掉落、首次通關獎勵與關係經驗。
9. 首次勝利播放戰後劇情，再返回區域地圖。
10. 玩家可重打舊關卡、強化角色與武器，再推進下一節點。
11. 擊破陸地首領後，區域地圖開放海洋航線，既有潮汐守望者成為海洋入口。

已讀的戰前或戰後劇情在重打時預設略過，但可由節點詳情主動重播。戰鬥結束後一律回到章節中樞，不再由結果頁硬編碼下一個畫面。

劇情資料由內容層定義，不把台詞硬編碼在 React 元件。每句台詞包含說話者、文字、站位、表情資產 ID 與可選的背景資產 ID。艦長台詞的資產 ID 依 `cap_m`／`cap_f` 自動解析；角色表情使用已交付的 neutral、happy、angry／tense、hurt 版本。

劇情播放器提供：

- 下一句。
- 對話紀錄。
- 整段略過。
- 已讀狀態。
- 從關卡詳情重播，重播不改變掉落、AP 或首通狀態。

主線劇情不顯示成人 CG。成人顯示模式不改變主線內容或關卡解鎖。

## 6. 區域地圖與導航

區域地圖是第二階段的主要中樞。視覺沿用深藍、黃銅、青色航線與人類工業文明語彙，四個節點沿左下到右上的地表遠征路線排列。

地圖頂列固定顯示：

- 目前 AP／30。
- 下一點 AP 的恢復倒數；滿 AP 時顯示「已滿」。
- 遠征補給劑數量與使用按鈕。
- 遠征點數。

選取節點後的詳情面板顯示：

- 名稱、關卡類型與故事摘要。
- 鎖定、可挑戰或已首通狀態。
- AP 消耗。
- 敵人名稱與屬性。
- 固定掉落與尚未領取的首通獎勵。
- 挑戰、重播戰前劇情及重播戰後劇情按鈕。

地圖功能入口包含：

- 角色強化。
- 武器盤／武器強化。
- 私人艙室。
- 顯示設定。
- 海洋航線；未解鎖時顯示明確條件。

現有 Formation 畫面在首次完成四人編隊後前往地圖。Loadout 畫面改為針對目前選取的關卡出擊，不再根據旗標猜測 Encounter。Cabin、Gallery 與 Settings 都能返回地圖。

## 7. AP 規則

常數如下：

- 上限：30。
- 恢復間隔：300,000 毫秒，即 5 分鐘 1 AP。
- 遠征補給劑：每個恢復 15 AP，套用 30 AP 上限。
- 新存檔：30 AP、補給劑 1。

AP 只在玩家從武器盤確認頁按下出擊時扣除。開啟節點、播放劇情或調整裝備不扣 AP。AP 不足時出擊按鈕停用並列出缺少值。

離線恢復使用最後結算時間戳計算：

1. `elapsed = max(0, now - lastRecoveredAt)`。
2. `restored = floor(elapsed / 300000)`。
3. AP 增加 `restored`，但不超過 30。
4. 未滿 AP 時保留不足 5 分鐘的餘數；已滿 AP 時把基準時間更新為目前時間，滿值期間不累積溢出。
5. 系統時間倒退時視為經過 0 毫秒，不扣除 AP。

結算時機包括讀取存檔、回到區域地圖、頁籤重新取得焦點與使用補給劑。

挑戰開始後保存 `activeChallenge`，其中包含節點、Encounter、已支付 AP 與戰鬥快照。每個回合結束後更新快照，因此重新整理會回到相同回合與生命狀態，不會再次扣 AP。

戰敗時：

- 全額退還 `activeChallenge.apCost`，但總 AP 仍不得超過 30。
- 不發放固定掉落、首通獎勵或關係經驗。
- 清除挑戰與戰鬥快照。
- 重試時重新檢查並扣除 AP。

勝利時不退 AP。獎勵與清除挑戰必須在同一個 reducer 動作內完成，避免重新整理重複領取。

## 8. 素材與獎勵

玩家持有：

- `expeditionPoints`：非付費通用貨幣。
- `surfaceAlloy`：地表合金。
- `ruinChip`：遺跡晶片。
- `leylineCore`：地脈核心。
- `fieldRation`：遠征補給劑。

所有數量都是大於等於 0 的安全整數。任何會產生負值、非整數或超過 JavaScript 安全整數的匯入存檔都視為無效。

關卡掉落為固定值，不使用亂數。首次通關追加只在節點第一次勝利時發放。結果頁分開列出固定掉落、首次通關追加、關係經驗與解鎖內容。

## 9. 角色與武器強化

四名角色與十二把武器分別保存 Lv.1–10。新存檔與遷移存檔全部從 Lv.1 開始；關係等級不轉換為戰鬥等級。

角色能力：

```text
multiplier = 1 + 0.04 × (level - 1)
effectiveAttack = round(baseAttack × multiplier)
effectiveMaxHp = round(baseMaxHp × multiplier)
```

武器能力：

```text
multiplier = 1 + 0.05 × (level - 1)
effectiveAttack = round(baseAttack × multiplier)
effectiveHp = round(baseHp × multiplier)
```

武器技能百分比與主手倍率不隨等級變動，避免同時引入第二套武器技能養成。

## 10. 資料模型與內容邊界

新增內容型別：

- `StageId`：四個陸地節點與海洋入口的穩定 ID。
- `StorySceneId`：八段陸地主線劇情 ID。
- `StageDefinition`：節點、Encounter、AP、固定掉落、首通獎勵與前後劇情。
- `StorySceneDefinition`／`StoryLineDefinition`：劇情資料與每句表情、站位。
- `Inventory`／`RewardBundle`／`UpgradeCost`：素材交易資料。

內容檔案分工：

- `src/content/stages.ts`：關卡圖與獎勵。
- `src/content/stories.ts`：八段劇情及台詞。
- `src/features/expedition/progression.ts`：解鎖、AP 與獎勵純函式。
- `src/features/growth/growth.ts`：等級成本與有效能力純函式。
- React 元件只負責顯示與派發動作，不自行重算交易規則。

GameState 升級至第 2 版，新增：

- AP 與最後恢復時間。
- Inventory。
- 角色及武器等級。
- 首次通關節點集合。
- 已讀劇情集合。
- 目前播放的劇情 ID 與劇情結束後的返回畫面。
- 目前選取節點。
- 目前挑戰、已支付 AP 與戰鬥快照。
- 最近一次關卡獎勵。

新增畫面：`expedition-map`、`story` 與 `growth`。既有 `loadout`、`battle`、`results`、`cabin`、`gallery`、`settings` 仍保留。

## 11. 第 1 版存檔遷移

存檔解析先辨識版本，再轉換為第 2 版並以第 2 版 schema 驗證。遷移規則：

- 保留成年確認、顯示模式、艦長、Roster、Party、武器盤、召喚、關係、旗標、已閱覽成人事件與最近結果。
- AP 設為 30，最後恢復時間設為遷移當下，補給劑設為 1。
- 素材與遠征點數設為 0。
- 所有角色與武器設為 Lv.1。
- 有 `flag_tutorial_victory` 時，將 `land_01_port_defense` 視為首通。
- 有 `flag_tidal_boss_victory` 時，將四個陸地節點全部視為首通、八段陸地劇情視為已讀並開放海洋入口；既有潮汐守望者勝利與成人事件進度保持不變。
- 舊存檔若停在 Cabin、Gallery 或 Settings，保留該畫面；已完成招募後的 Formation、Loadout、Battle 或 Results 統一回到區域地圖，避免建立未支付 AP 的半套挑戰。
- 未完成招募的 onboarding 畫面保持原流程。

無法遷移或通過第 2 版 schema 的資料沿用目前的損壞存檔復原機制，建立全新狀態並保存可診斷訊息，不部分採用無效資料。

## 12. 錯誤與交易一致性

- `START_STAGE` 同時同步 AP、驗證解鎖與 Party、扣除 AP、建立挑戰；任一步失敗都不改狀態。
- `FINISH_STAGE_VICTORY` 同時發獎、記錄首通、增加關係經驗、清除挑戰與建立結果；不能分成可重複觸發的多個公開動作。
- `FINISH_STAGE_DEFEAT` 同時退還 AP、清除挑戰與建立失敗結果。
- `UPGRADE_CHARACTER`／`UPGRADE_WEAPON` 同時驗證等級、所有權及完整成本，再扣除素材並升級。
- 重播劇情只改已讀狀態，不重複發獎。
- 頁籤恢復與定時器同時觸發 AP 同步時，以 reducer 內的時間戳計算確保冪等。
- 遺失美術繼續使用既有安全替代圖；單張資產不存在不阻斷地圖、劇情或戰鬥。

## 13. 測試策略

### 13.1 純函式與 Reducer

- 線性關卡解鎖、海洋入口條件與重打。
- AP 正常恢復、餘數、滿值、系統時間倒退與補給劑上限。
- 開始關卡的原子扣款與 AP 不足拒絕。
- 戰敗全額退款、勝利不退款與重新整理不重複扣款。
- 固定掉落、首通追加一次性與獎勵整數不變量。
- 角色／武器 Lv.1、Lv.10 數值與每級成本。
- 素材不足、滿級、未持有武器與非法動作拒絕。
- 第 1 版存檔的教學旗標、潮汐首領旗標及損壞資料遷移。

### 13.2 元件

- 地圖節點的鎖定、首通、AP 與掉落顯示。
- AP 倒數與補給劑互動。
- 劇情艦長性別資產、角色表情、下一句、紀錄、略過及重播。
- Growth 分頁、能力預覽、缺少素材與滿級狀態。
- Loadout 針對選定節點出擊，不再自動猜 Encounter。
- Results 顯示固定掉落、首通追加、退款與下一步。

### 13.3 端對端

- 全新男性與女性艦長：onboarding → 四個陸地節點 → 海洋入口。
- 重打關卡取得素材，角色與武器各升一級，下一場戰鬥使用提升後數值。
- AP 不足時使用補給劑後出擊。
- 戰敗退還 AP，重試重新扣款。
- 重新載入進行中的挑戰，回到相同戰鬥快照且不重複扣 AP。
- 遷移已有潮汐守望者勝利與成人收藏的第 1 版存檔。
- 1280×720、1440×810、1920×1080 三種桌面尺寸完成主要流程。

## 14. 完成標準

- 玩家能從成年確認完整推進至陸地首領並開放潮汐守望者。
- 四個節點可重打，AP、掉落、首通獎勵及戰敗退款一致。
- 角色與武器能升至 Lv.10，提升後能力實際進入戰鬥計算。
- 八段劇情能正常播放、略過、重播並使用正確表情素材。
- 第 1 版存檔遷移不丟失現有關係、收藏、隊伍及武器盤。
- 成人收藏仍與主線進度及戰鬥數值隔離。
