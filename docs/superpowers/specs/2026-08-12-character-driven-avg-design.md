# 第一大章角色驅動 AVG 改編設計

> 日期：2026-08-12
>
> 適用範圍：第一大章八名重要角色、三十幕人物狀態與 AVG 劇本重製
>
> 設計狀態：已由使用者逐段確認

## 一、目標

將目前由小說機械切分而成的三十幕內容，重製為由角色設定約束的 AVG 劇本。

- 第一大章小說 v0.2 與三十幕細綱固定故事框架、外部事件、關係轉折、不可逆結果及章末狀態。
- 小說正文只作為世界、事件、場景與情感素材，不再逐句搬入遊戲。
- 劇情方向以已確定的三十幕正史為準。
- 人物在事件中的選擇、應對、語氣、動作及關係表現，必須由人物演出卡與當幕狀態決定。
- AVG 台詞重新編寫，不以自動推斷說話者或固定整幕演員陣容產生。

## 二、正史與創作權限

### 固定內容

- 三十幕的排列順序、視點人物、外部事件與因果。
- 每幕的關係轉折及幕末不可逆結果。
- 第 15、20、25 幕三段正史 R18 關係內容。
- 章末的船權、航照、職務、船員、制衡與公開關係狀態。
- 世界聖經已定案的制度、國家利益、深洋與力量上層約束。

### 可改編內容

- 場景內的台詞、對話順序、停頓、反應與肢體演出。
- 不影響固定因果的場面濃縮、拆分與銜接。
- 必要旁白、視點內心、進退場及鏡頭節奏。
- 為使固定結果符合人物邏輯而補足的資訊、壓力、限制或代價。

### 不允許的處理

- 為保留小說原句而讓人物違反角色卡。
- 讓角色突然全知、降智或跨越專業權限推動事件。
- 改變固定結果，或使用好感度分歧主線正史。
- 用親密關係取消職務、退出、拒絕、追責及中止權。

## 四、人物演出卡

每張人物卡必須將抽象形容轉為可觀察、可檢查的演出規則，包含以下內容。

### 4.1 固定基本資料

- 姓名、年齡、出身、文化、教育與職業履歷。
- 岸上及船上職責、能力範圍、正式權限與不可越界的專業領域。
- 外觀特徵、服裝習慣、生活習慣及可持續使用的視覺辨識點。

### 4.2 人格核心

- 公開目標與私人需要。
- 核心恐懼、錯誤信念及自尊來源。
- 價值順位、可承受代價與不可接受底線。
- 會傷害自己、關係或任務的缺點。

### 4.3 決策邏輯

分別定義人物在下列狀態的判斷順位與行為傾向：

- 日常與低壓狀態。
- 專業衝突與公開問責。
- 緊急事故與時間壓力。
- 犯錯、被質疑及失去控制。
- 嫉妒、依戀、拒絕與親密。

### 4.4 說話方式

- 慣用詞彙、句長、語速與直接程度。
- 提問、命令、拒絕、說謊、迴避、道歉及示弱的方式。
- 職務場合、私人場合、憤怒、疲憊與親密狀態的差異。
- 面對不同對象時的稱呼、攻擊方式、沉默方式及可暴露的脆弱程度。

### 4.5 身體演出

- 基本站姿、視線、手部習慣及移動方式。
- 壓力反應、情緒失控前兆及恢復控制的動作。
- 接近距離、觸碰界線、主動或被動退讓方式。
- 進場、退場、沉默及聆聽時可辨識的演出。

### 4.6 能力與資訊邊界

- 擅長、不擅長及必須依賴他人的事項。
- 每階段已知、未知、誤解與刻意隱瞞的資訊。
- 可以提出的專業判斷及不得替其他席位回答的問題。

### 4.7 成長與禁止偏離

- 章初、重大轉折及章末的人格與行為變化。
- 絕對不能出現的台詞、選擇、權力使用與關係處理。
- 成長不能消除的缺點、嫉妒、戒心及專業分歧。

### 4.8 演出校驗附件

每張人物卡附上：

- 正確與錯誤台詞對照。
- 正確與錯誤動作對照。
- 日常、任務、壓力、爭執及親密情境範例。
- 寫完一場戲後可逐項使用的人物一致性檢查表。

## 五、人物關係系統

八名角色的 28 組兩兩關係均建立基礎資料；直接影響三十幕主線的關係建立完整演出規則。

每組關係記錄：

1. 表面身分與私下真實關係。
2. 雙方職務權力、依賴及制衡方式。
3. 各自想從對方取得的需要與害怕受到的傷害。
4. 最常發生的誤解、信任來源、衝突來源及底線。
5. 專屬稱呼、語氣、句長、試探、攻擊、沉默與示弱方式。
6. 專屬肢體距離、視線、觸碰與退讓方式。
7. 爭執、逃避、道歉、修復與恢復合作的合理過程。
8. 三十幕內每次共同登場造成的具體關係變化。

第一章感情進展使用固定正史狀態，不以好感度改變結果。親密關係成立後，既有嫉妒、傷害、戒心及職務衝突仍須延續，不能以一句信任或道歉消除。

## 六、三十幕人物狀態表

每幕建立一份可供編劇及資料校驗使用的狀態記錄：

- 小說已固定的事件、視點、關係轉折與不可逆結果。
- 場景分段、實際登場者、進場時點、退場時點及留在畫面的理由。
- 各角色當時已知、未知、誤解及隱瞞的資訊。
- 從前一幕延續的情緒餘波及本幕進場情緒。
- 當幕公開目標、私人意圖、決策順位及不能採取的行為。
- 每段對話的意圖與潛台詞，不預先綁死小說原句。
- 表情、視線、站位、距離、動作與沉默的演出功能。
- 戰鬥前後的劇情銜接、實際參戰者及勝利代價。
- 幕末人物、情報、職務與關係狀態更新。

三十幕狀態表依六個故事階段分成六份文件，每份涵蓋五幕，以便逐階段審查。

## 七、AVG 編劇與節奏規則

每幕以以下節奏重新編寫：

> 開場鉤子 → 當幕目標 → 人物衝突或合作 → 關鍵轉折 → 不可逆結果 → 下一幕鉤子

### 7.1 台詞

- 所有台詞依角色演出卡重新口語化，可濃縮、改寫或調整場內順序。
- 每句台詞必須有明確目的，例如試探、拒絕、隱瞞、推進、施壓、示弱或改變關係。
- 說話者由編劇資料人工指定，不再使用上下文輪替猜測。
- 不用完整公文、設定說明或小說描述充當角色口語；必要資訊拆入問答、行動結果或畫面。

### 7.2 旁白

- 只用於轉場、時間變化、限知視點內心及現有畫面無法表現的必要資訊。
- 不重述畫面已呈現的動作，也不複述角色剛說過的內容。
- 原則上不連續超過兩句；例外必須具有不可替代的視點或轉場功能。

### 7.3 舞台演出

- 角色只在實際參與場面時登場，並在場面結束或離開後退場。
- 每節可指定人物站位、表情、視線與動作變化。
- 沉默必須以避開目光、收回手、檢查工具、改變距離等可觀察反應表達，不能讓角色無目的站樁。
- 未說話但留在畫面的角色必須具有聆聽、監督、威脅、等待或關係反應等演出理由。

### 7.4 篇幅

- 一般幕預估 45 至 80 節。
- 重大情感、揭露或複合事件幕可使用 70 至 110 節。
- 全章預估約 1,800 至 2,400 節，取代目前機械切分的 4,914 節。
- 節數是節奏檢查指標，不是硬性配額；不得為達數字加入無功能台詞。

### 7.5 R18 正史幕

- 第 15、20、25 幕保留為三段正史成人內容。
- 每幕至少配置三張 CG，實際分鏡依已核准美術資產與人物狀態安排。
- 所有親密演出遵守明確成年、意識清楚、能自由離開及重新確認同意的既有護欄。
- 親密不交換職權、情報、醫療、留船資格或戰鬥能力。

AVG 劇本改用手工編寫、由 TypeScript 型別約束的場景模組：

```text
src/chapter-one/story/
├─ schema.ts
├─ validate.ts
├─ index.ts
└─ scenes/
   ├─ scene-01.ts
   ├─ ...
   └─ scene-30.ts
```

每個節點保存完整舞台快照，而非只保存相對的進場或退場命令。前進、後退及讀檔時可直接還原正確舞台；介面動畫則比較前後快照產生。原小說 Markdown 不再直接生成遊戲台詞，也不得用來猜測說話者或整幕演員陣容。

## 九、遊戲資料模型要求

每個 AVG 節點至少明確記錄：

- 說話者及顯示名稱。
- 台詞或必要旁白。
- 實際在場角色。
- 角色進場、退場、位置、表情及動作。
- 背景、CG、音訊及必要轉場。
- 當幕與來源追溯資料。

靜態校驗必須能偵測：

- 不存在、未登場或已退場的角色說話。
- 同一位置的角色衝突及超出舞台容量。
- 說話者與顯示名稱不一致。
- 過量連續旁白、異常長台詞及長時間無演出功能的站場角色。
- 三十幕順序、固定事件結果、R18 CG 數量及戰鬥插入點偏離正史。

## 十、製作順序與審查關卡

1. 完成八張人物演出卡並統一資料正準。
2. 完成 28 組人物關係矩陣。
3. 完成六階段三十幕人物狀態表。
4. 由使用者審查人物設定與固定劇情方向。
5. 重寫第一幕作為完整 AVG 演出樣板。
6. 由使用者確認第一幕節奏、語氣、進退場與舞台效果。
7. 依樣板重寫其餘二十九幕。
8. 每五幕執行一次人物一致性、正史事件及遠端遊戲 QA。

若固定事件的原過程與人物卡衝突，保留已核准的事件結果，重新設計促使人物合理選擇的資訊、壓力、限制或代價；不得強迫人物降智，也不得自行改變結果。

### 10.1 工作拆分

本設計是總體正準，後續分成四個可獨立審查的實作階段，不以單一巨型計畫一次完成：

1. **人物演出聖經：**八張 v0.3 人物卡、姓名與年齡正準。
2. **人物關係與逐幕狀態：**28 組關係矩陣及六份三十幕狀態表。
3. **第一幕垂直樣板：**資料模型、校驗器、舞台演出及第一幕完整 AVG。
4. **全章改編：**依樣板完成其餘二十九幕，每五幕審查與遠端 QA。

每一階段均須承接上一階段已核准的文件；發現矛盾時先回修上游正準並取得確認，不在下游劇本中私自繞過。

## 十一、驗證與 QA

### 文件驗證

- 八張人物卡均具備完整欄位、示例及一致性檢查表。
- 28 組關係均有基礎資料，主線核心關係有逐幕演變。
- 三十幕均具有在場、資訊、情緒、目標、演出及幕末更新。
- 姓名、年齡、職務、視點、關係狀態與世界觀文件一致。

### 劇本驗證

- 每句對話均可追溯到角色卡的說話與決策規則。
- 每個固定事件結果均存在合理的人物選擇、資訊與代價鏈。
- 說話者、在場者、進退場、表情及動作均為人工明確資料。
- 無角色長時間無目的站樁，無機械輪替猜測，無小說段落直接當作遊戲稿朗讀。

### 專案 QA 限制

- 不啟動本機 Vite、預覽或靜態伺服器。
- 不以本機測試、建置、E2E 或美術驗證作為驗收。
- 每次遊戲資料完成後推送工作分支，執行 `Remote QA - GitHub Pages`。
- 手動及自動瀏覽器 QA 只使用固定網址：
  `https://lialialialia1211-debug.github.io/astra-voyage-slice/`
- 完成報告必須包含 Pages URL、GitHub Actions run URL、部署 commit SHA 與遠端 QA 結果。

## 十二、完成定義

本重製工作完成時，必須同時滿足：

- 八名角色具有足以約束台詞、動作、選擇與關係的詳細演出卡。
- 三十幕具有逐幕人物狀態與固定正史追蹤。
- 遊戲不再從小說自動猜測說話者或固定整幕角色站場。
- 三十幕均完成角色驅動 AVG 改編並接回既有戰鬥流程。
- 第一幕附圖中的說話者錯位、念稿感與晏泠全程站樁三類問題，在資料規則與實際演出中一併消除。
- 遠端 GitHub Pages QA 通過。
